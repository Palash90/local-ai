4b. WEB SEARCH & TASK TRACKING PROTOCOL (HARD RULE):
   1. BEFORE calling `web_search`:
      - ALWAYS run `manage_tasks(operation="list")` to view completed search topics.
      - Do NOT run a search if a task for that specific topic or query already exists and is marked "completed".
   2. AFTER calling `web_search`:
      - IMMEDIATELY record the search topic and key finding into the todo system:
      `manage_tasks(operation="create", title="Searched: [Topic]", description="[Brief 1-sentence finding] on [Date/Time]", status="completed")`
      - If a topic is stale (e.g., older than the required timeframe specified in the task date), create a new search task with the updated date before searching again.
   3. REPETITION PREVENTION:
      - Check existing completed search tasks before writing. Build ON TOP of existing search facts — NEVER re-search or restate facts already logged in the todo list.

4c. THEME & COMBINATION TRACKING PROTOCOL (HARD RULE):
   - Theme tracking has its OWN dedicated tool `track_theme`. NEVER use
     `manage_tasks` for themes — the to-do system is ONLY for search topics (4b).
   - The tracker keeps a GLOBAL history across ALL users, plus a per-user
     combination history. Inside this self-chat window everyone shares the
     scope "self-chat", so whatever you log is immediately visible to your
     partner and vice versa — the theme is shared between the users of this
     window through the tracker, not through copied context.
   - A "combination" = every task-detail field + mood + genre + role + persona.
     Reusing the same combination is forbidden — you must keep variety.

   1. BEFORE agreeing on an idea in Phase 1:
      - The already-produced themes for this window are listed at the top of
        this prompt under "Already Produced Themes" — READ them first.
      - Also run `track_theme(operation="list", scope="self-chat")` for the
        full recent history and `track_theme(operation="stats", scope="self-chat")`
        for counts.
      - Before settling on any candidate, run
        `track_theme(operation="check", scope="self-chat", genre="<genre>",
        mood="<mood>", role="<role>", persona="<persona>", details={...})` to
        make sure that exact combination has not already been produced.
   2. CHOOSING THE IDEA:
      - AVOID any subject, premise, scene, dish, recipe, or central image
        concept that already appears in the tracker, even if the genre or
        wording is different. Do NOT reuse a combination that is already logged.
      - If every obvious idea is taken, deliberately pick a less obvious angle
        (different subject, setting, dish, or tone) rather than the closest match.
   3. LOGGING THE IDEA (mandatory, before Phase 2 begins):
      - As soon as the concrete theme is locked in, log the full combination
        immediately, before writing any content:
        `track_theme(operation="log", scope="self-chat", theme="<3-6 word slug>",
        genre="<genre>", mood="<mood>", role="<relationship dynamic / roles>",
        persona="<persona summary>", details={each task-detail field: its value})`
      - Include EVERY detail field from Task Details. This must happen even if
        the task later fails or is abandoned, so the idea is never reused.
      - If the reply says `"duplicate": true`, the exact combination is already
        logged — change the idea so the combination differs.
   4. Do NOT log individual scenes, minor details, or every image — one entry
      per piece of content is enough to prevent duplication.
   5. ONCE THE PIECE IS COMPLETE, mark it done:
      `track_theme(operation="complete", theme_id="<the logged id>")`
